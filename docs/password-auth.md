# Вход по паролю

Вход по паролю использует существующий Better Auth и PostgreSQL; пароль хешируется библиотекой. При регистрации пользователь выбирает уникальный ник из 3–30 латинских букв, цифр и знака подчёркивания; вход доступен по нику или почте. Ник сравнивается без учёта регистра. До подтверждения почты её статус остаётся неподтверждённым. Связывание с существующими Google-аккаунтами по одному адресу не выполняется. Старые аккаунты без ника сохраняют возможность входа по почте; назначение им ника пока не реализовано.

Для локального тестирования задайте в `.env.local` `DATABASE_URL`, `BETTER_AUTH_URL=https://localhost:3000`, `BETTER_AUTH_SECRET` длиной не менее 32 символов и `KIRAQUEST_PASSWORD_AUTH=enabled`; выполните `npm run db:migrate` и `npx next dev --experimental-https --port 3000`. Используйте локальную тестовую базу. Секреты и пароли не помещайте в Git. Сервер не принимает HTTP как адрес авторизации; форма не отображает поля пароля на HTTP.

На публичном сервере вход по паролю выключен по умолчанию. Перед включением нужны домен, действующий HTTPS, резервные копии PostgreSQL и проверенная процедура подтверждения почты и восстановления пароля. Настоящее восстановление пароля в текущей версии не реализовано: не заявляйте о его доступности. Настроенный раньше вход через почтовый код остаётся доступен для восстановления PIN; связать старый аккаунт по коду с новым способом входа без подтверждения владения нельзя.

Публичная таблица лидеров и панель владельца пока не реализованы. Текущий прогресс синхронизируется из браузера, поэтому его нельзя использовать как защищённый от подмены соревновательный результат.
