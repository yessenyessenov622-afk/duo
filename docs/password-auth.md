# Вход и регистрация по паролю

Авторизация использует Better Auth, серверные сессии и PostgreSQL. Новые пароли хешируются Argon2id; существующие scrypt-хеши Better Auth остаются совместимыми. Для регистрации нужны уникальный ник (3–30 латинских букв, цифр или `_`), электронная почта и пароль длиной 12–128 символов. Форма входа использует email. Формы доступны на `/register` и `/sign-in`. HTTP намеренно не показывает поля пароля и не является допустимым адресом авторизации.

Функция выключена по умолчанию. На сервере должны быть заданы `DATABASE_URL`, `BETTER_AUTH_URL` с точным HTTPS-адресом сайта, `BETTER_AUTH_SECRET` длиной не менее 32 символов, `KIRAQUEST_PASSWORD_AUTH=enabled` и настроенная почтовая доставка (Resend либо тестовый [SendGrid](sendgrid-testing.md)). Без почты парольный вход остаётся выключен. Секреты и пароли не помещайте в Git или чат. После успешного входа Better Auth выдаёт Secure/HttpOnly cookie; учетная запись, прогресс, XP, настройки и маскот хранятся по ID пользователя в существующей PostgreSQL.

Для локальной проверки используйте отдельную тестовую базу и `.env.local`, задайте `BETTER_AUTH_URL=https://localhost:3000`, затем выполните `npm run db:migrate` и `npx next dev --experimental-https --port 3000`. Не включайте парольный вход на публичном сервере, пока не проверены HTTPS, регистрация, неверный пароль, выход, повторный вход, сохранение/изоляция данных и резервные копии.

## HTTPS без покупки домена

Покупать собственный домен не обязательно для технической проверки:

- **ngrok Free** выдаёт HTTPS и один закреплённый за аккаунтом адрес вида `*.ngrok-free.app`; нужен аккаунт, установленный агент и его токен на сервере. Бесплатный план имеет квоты (в частности, 1 GB и 20 000 HTTP-запросов в месяц) и показывает посетителям предупреждающую страницу. Это удобный вариант временного публичного запуска с малой нагрузкой, но зависимостью от стороннего сервиса и его лимитов. Проверьте текущие условия у [ngrok](https://ngrok.com/docs/pricing-limits/free-plan-limits/).
- **nip.io/sslip.io + Let's Encrypt** позволяет направить имя вида `<публичный-IP>.nip.io` на уже существующий сервер и получить сертификат. Нужен доступ к настройкам сервера, открытый входящий порт 80 для HTTP-01 проверки и reverse proxy с автоматическим продлением сертификата (например, Caddy). Это сторонний бесплатный DNS, не собственный домен; имя связано с публичным IP и не переносится при его смене. Сам сервер и публичный IPv4 в AWS могут иметь стоимость; новые ресурсы для этого не создаются.
- **Cloudflare Quick Tunnel** даёт случайный `trycloudflare.com` HTTPS-адрес без аккаунта и домена, но он меняется при перезапуске и официально предназначен только для тестирования. Это не постоянный адрес для входа: при смене адреса серверную `BETTER_AUTH_URL` тоже надо менять. См. [ограничения Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

Для стабильного недорогого адреса без покупки домена разумно начать с закреплённого адреса ngrok Free, если устраивают квоты, промежуточное предупреждение и требования их бесплатного плана. Владелец должен сам создать/подтвердить аккаунт провайдера и безопасно настроить агент и его токен на имеющемся сервере. Не передавайте токен в чат и не сохраняйте его в репозитории. После выбора адреса владелец должен задать точный `BETTER_AUTH_URL`, проверить HTTPS и обновить redirect URI у OAuth-провайдера, если Google-вход используется.

## Прогресс гостя и смена адреса

Гостевой прогресс хранится в браузере раздельно для каждого origin (протокол, имя сайта и порт). Он не переносится автоматически с HTTP/IP на HTTPS-адрес или другой домен. На старом адресе открой профиль и скачай `kiraquest-guest-backup.json`; на новом войди в аккаунт и подтверди перенос/объединение. Перенос объединяет уникальные уроки и не начисляет XP повторно. Исходные данные старого браузера и резервный файл остаются на месте после переноса. Сам файл содержит приватные данные прогресса и оформления — храни его безопасно.

## Ограничения публичного запуска

Перед входом новый пользователь подтверждает почту одноразовым кодом. Восстановление пароля использует одноразовую ссылку со сроком действия 30 минут и отзывает прежние сессии; оно не добавляет пароль к аккаунту только с Google. Перед публичным включением необходимо настроить и проверить доставку реальных писем, оба сценария, HTTPS и резервные копии базы. Старые аккаунты без ника по-прежнему могут войти по почте после подтверждения; существующие Google-аккаунты автоматически не связываются по одному адресу.

Учебный прогресс синхронизируется с сервера после отправки клиентского состояния, поэтому его не следует считать защищённым от подмены соревновательным результатом. Таблица лидеров и панель владельца не реализованы.
