# Вход по почте: локальная проверка

Функция проверена локально с отдельной PostgreSQL и тестовым почтовым транспортом. До публичного запуска необходимы реальные письма, HTTPS, проверка реального входа и аудит конфигурации. Гостевое хранилище отдельно для каждого адреса сайта; для переноса между адресами скачай `kiraquest-guest-backup.json` на старом адресе и загрузи его в профиле на новом.

Для локальной разработки подготовьте PostgreSQL и скопируйте `.env.example` в `.env.local`; задайте `DATABASE_URL`, `BETTER_AUTH_SECRET` длиной не менее 32 символов, `BETTER_AUTH_URL=https://localhost:3000` и `KIRAQUEST_MAIL_MODE=development`. Отдельный Google-клиент для входа по коду не обязателен. Запустите `npm run db:migrate`, затем `npx next dev --experimental-https --port 3000`. Доверенный локальный HTTPS-сертификат нужен для проверки защищённых cookies. Код показывается только в терминале сервера разработки, настоящие письма не отправляются. На production этот режим отклоняется.

Для реальных писем можно настроить Resend с подтверждённым доменом отправителя и серверными переменными `KIRAQUEST_MAIL_MODE=resend`, `RESEND_API_KEY` и `KIRAQUEST_MAIL_FROM`. Альтернативный тестовый вариант — [SendGrid](sendgrid-testing.md); его фактические ограничения и доставку необходимо проверить на собственном аккаунте. Ключ не записывайте в Git и не пересылайте в чат. В production требуется HTTPS-адрес. Отправка не подключена и не проверена.

Почтовый вход не связывает автоматически существующие Google-аккаунты: для них понадобится отдельно проверенный процесс связывания. Если Google настроен, такие пользователи продолжают входить и восстанавливать PIN через Google. Исходный гостевой прогресс остаётся в браузере после переноса.
